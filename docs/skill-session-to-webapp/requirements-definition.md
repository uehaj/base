# 要件定義書: セッションやりとりの WEB アプリ化スキル（session-to-webapp）

- 文書番号: DEF-S2W-001
- 版: 0.1（ドラフト）
- 作成日: 2026-07-11
- 上位文書: 要求仕様書 REQ-S2W-001（`requirements-spec.md`）
- ステータス: 要求仕様書 §9 の問いに回答後、0.2 へ改版

## 1. システム概要

本スキルは、Claude Code セッション内で起動され、以下を自動で行う。

1. セッションの成果物から WEB アプリ（静的 UI + アップロード受付 + 処理実行部）を組み立てる
2. 作成者に同梱内容・公開範囲を提示し、承認を得る
3. cf-apps 環境へデプロイし、公開 URL を払い出す
4. ライフサイクル終端で、アプリとすべてのデータを削除する

### 1.1 構成図

```
┌─ Claude Code セッション ─────────────────┐
│  /session-to-webapp（本スキル）           │
│   ├─ 1. 収集: 手元のファイル・処理を選定  │
│   ├─ 2. 生成: アプリ雛形に組み込み        │
│   ├─ 3. 承認: 同梱内容を作成者へ提示      │
│   └─ 4. デプロイ / 破棄（cf-apps API/CLI）│
└──────────────┬───────────────────────────┘
               ▼
┌─ cf-apps 環境（使い捨てアプリ 1 個）──────┐
│  静的配信層: 手元のファイルを無加工で配信  │
│  アプリ UI : アップロード / 実行 / 結果DL  │
│  実行層    : 隔離サンドボックスで処理実行  │
│  一時領域  : アップロード・中間・出力      │
│  ※ 終了時にアプリごと全削除               │
└───────────────────────────────────────────┘
               ▲
        利用者（ブラウザ）
```

### 1.2 成果物（本スキル実装時の構成）

| 成果物              | 内容                                                                      |
| ------------------- | ------------------------------------------------------------------------- |
| `SKILL.md`          | スキル定義（起動条件・手順・引数）                                        |
| `scripts/collect.*` | 同梱ファイル・処理エントリポイントの選定と manifest 生成                  |
| `scripts/deploy.*`  | cf-apps へのデプロイ・URL 払い出し・削除                                  |
| `template/`         | アプリ雛形（アップロード UI、ジョブ実行、TTL/自己消滅、結果ダウンロード） |
| 本ドキュメント一式  | 要求仕様書・要件定義書                                                    |

## 2. 機能要件（FR）

対応する要求（UR）を併記する。優先度は要求仕様書に準ずる。

### 2.1 スキル起動・アプリ生成

| ID    | 要件                                                                                                                                    | 対応 UR   |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| FR-01 | スキルはセッション内から引数なしで起動でき、対話的に (a) 同梱する静的ファイル、(b) 処理エントリポイント、(c) 有効期限、を決定できること | UR-01     |
| FR-02 | 同梱ファイルは作成者の明示選択制とし、既定では何も同梱しないこと。`.git`・環境変数・認証情報・`workdir/` 等は選択候補から除外すること   | UR-03, 07 |
| FR-03 | 選定結果は manifest（同梱ファイル一覧、処理コマンド、制限値、TTL）として作成者に提示し、承認を得てからデプロイすること                  | UR-07     |
| FR-04 | 生成されるアプリは、雛形（template）に manifest と成果物を注入する方式とし、セッションごとのコード生成を最小化すること                  | UR-01     |
| FR-05 | デプロイ完了時に公開 URL・有効期限・破棄方法を作成者に提示すること                                                                      | UR-02     |

### 2.2 静的配信

| ID    | 要件                                                                                                               | 対応 UR |
| ----- | ------------------------------------------------------------------------------------------------------------------ | ------- |
| FR-06 | 同梱された手元のファイルは、内容を一切変換せず（バイト同一で）静的配信されること。パスはアプリ内の `/static/` 配下 | UR-03   |
| FR-07 | `index.html` が同梱されている場合はそれをトップページにできること。ない場合は雛形の標準 UI を表示すること          | UR-03   |

### 2.3 アップロードと処理実行

| ID    | 要件                                                                                                                | 対応 UR   |
| ----- | ------------------------------------------------------------------------------------------------------------------- | --------- |
| FR-08 | 利用者は処理開始前に 1 つ以上のファイルをアップロードでき、アップロード済み一覧を確認・削除できること               | UR-04     |
| FR-09 | アップロードには上限（既定案: 1 ファイル 25MB、合計 100MB、20 件。要確認 Q5）を設け、超過時は明確なエラーを返すこと | UR-04     |
| FR-10 | 処理は「開始」操作で明示的に起動され、アップロードファイルのみを入力として隔離環境で実行されること                  | UR-04, 05 |
| FR-11 | 実行中は進行状況（実行中/完了/失敗、経過ログの要約）を利用者に表示すること                                          | UR-08     |
| FR-12 | 処理の出力ファイルは利用者がダウンロードできること                                                                  | UR-08     |
| FR-13 | 実行には時間上限（既定案: 5 分）を設け、超過時は強制終了し利用者へ通知すること                                      | UR-05     |

### 2.4 隔離

| ID    | 要件                                                                                                                                 | 対応 UR   |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------ | --------- |
| FR-14 | 処理はアプリ専用のサンドボックス（cf-apps の隔離実行機構）内で実行され、ファイルシステム・プロセスが他アプリ・他実行と分離されること | UR-05     |
| FR-15 | サンドボックスからの外部ネットワークアクセスは既定で遮断すること（処理が必要とする場合は manifest で宛先を明示許可。要確認 Q7）      | UR-05     |
| FR-16 | 実行ごとに作業領域を初期化し、前の利用者の入力・出力が次の実行から参照できないこと                                                   | UR-05, 06 |

### 2.5 ライフサイクル・消去

| ID    | 要件                                                                                                                                                       | 対応 UR   |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| FR-17 | アプリには TTL（既定案: 24 時間、要確認 Q3）を設定し、満了時に自動で終了すること                                                                           | UR-06, 10 |
| FR-18 | 作成者はスキル（またはデプロイ時に提示される操作）からアプリを即時破棄できること                                                                           | UR-10     |
| FR-19 | 終了時、以下をすべて削除すること: アプリ本体（配信物・コード）、アップロードファイル、中間生成物、出力ファイル、アプリ内ログのうち入力データを含み得るもの | UR-06     |
| FR-20 | 終了後の URL アクセスには「終了済み」を示す応答（410 相当）または接続不能となること                                                                        | UR-06     |
| FR-21 | デプロイ・破棄は冪等とし、途中失敗時にリトライまたはロールバックで中途半端なリソースを残さないこと                                                         | UR-06     |

### 2.6 アクセス制御・管理（Should/Could）

| ID    | 要件                                                                                              | 対応 UR |
| ----- | ------------------------------------------------------------------------------------------------- | ------- |
| FR-22 | アプリ URL は推測困難なランダムパスを含むこと。オプションで簡易トークンによる保護を選択できること | UR-09   |
| FR-23 | （Could）作成者は自分が公開中のアプリの一覧（URL・残り TTL）を確認できること                      | UR-11   |
| FR-24 | （Could）同一セッションから再デプロイした場合、既存アプリを破棄してから置き換えること             | UR-12   |

## 3. 非機能要件（NFR）

| ID     | 分類         | 要件                                                                                                                                           |
| ------ | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| NFR-01 | セキュリティ | 秘密情報（環境変数・トークン・鍵ファイル）をアプリに同梱しない。デプロイ前に同梱物へ秘密情報検査（パターン検出）を行い、検出時は警告・確認する |
| NFR-02 | セキュリティ | アップロードファイルは実行対象にしない（入力データとしてのみ扱う）。Content-Type を検証し、配信時は `nosniff` 等の防御ヘッダを付与する         |
| NFR-03 | プライバシー | 利用者のアップロード内容・処理結果を、cf-apps の永続ログや作成者側環境に残さない                                                               |
| NFR-04 | 性能         | 同時利用者 10 人程度・同時実行ジョブ数（既定案: 2、超過はキュー待ち）で安定動作すること                                                        |
| NFR-05 | コスト       | 無操作時に課金対象の常駐リソースを保持しない。TTL 満了で確実に課金が止まること                                                                 |
| NFR-06 | 可用性       | 使い捨て用途のため SLA は定めない。ただしジョブ実行中の予期せぬ終了時は利用者へ失敗を明示すること                                              |
| NFR-07 | 運用性       | デプロイ〜破棄まで作成者の操作はスキル内で完結し、cf-apps コンソールの手動操作を必要としないこと                                               |
| NFR-08 | 保守性       | 雛形・スクリプトは本リポジトリの規約（Node 22 / pnpm、Python 3.13 / uv、lint/format/test）に適合すること                                       |

## 4. インタフェース要件

### 4.1 作成者インタフェース（スキル）

- 起動: `/session-to-webapp`（引数で TTL・トークン保護の有無を指定可能）
- 対話: 同梱ファイル選択 → 処理エントリポイント指定 → manifest 確認・承認 → デプロイ
- 出力: 公開 URL、（トークン保護時の）アクセストークン、有効期限、破棄コマンド

### 4.2 利用者インタフェース（WEB）

| 画面/API          | 内容                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| トップページ      | アプリ説明、静的コンテンツへの導線、アップロード UI、残り有効期限表示 |
| `POST /upload`    | ファイルアップロード（制限値超過は 4xx）                              |
| `POST /run`       | 処理開始（アップロード済みファイルを入力に実行）                      |
| `GET /status`     | 実行状態・進行状況                                                    |
| `GET /result/...` | 出力ファイルのダウンロード                                            |
| `GET /static/...` | 同梱静的ファイル（無加工）                                            |

### 4.3 外部インタフェース

- cf-apps のデプロイ/削除 API（認証情報は環境変数から取得。要確認 Q1）

## 5. データ要件とライフサイクル

| データ               | 保存場所                | 生成         | 消滅                                           |
| -------------------- | ----------------------- | ------------ | ---------------------------------------------- |
| 同梱静的ファイル     | cf-apps 配信領域        | デプロイ時   | アプリ終了時                                   |
| 処理コード           | cf-apps 実行領域        | デプロイ時   | アプリ終了時                                   |
| アップロードファイル | アプリの一時領域        | 利用者の操作 | 実行完了後の掃除、遅くともアプリ終了時         |
| 中間生成物・出力     | サンドボックス内        | 実行時       | 実行完了後の掃除、遅くともアプリ終了時         |
| 実行ログ（表示用）   | アプリのメモリ/一時領域 | 実行時       | アプリ終了時（永続ログへ書き出さない）         |
| manifest             | セッション作業領域      | スキル実行時 | セッション終了とともに（リポジトリ非コミット） |

## 6. 受け入れ基準（要件レベルの試験観点）

| #   | 試験観点                                                                                                          | 対応要件  |
| --- | ----------------------------------------------------------------------------------------------------------------- | --------- |
| T1  | スキル起動から承認・デプロイまでを実施し、公開 URL が払い出される                                                 | FR-01〜05 |
| T2  | 同梱した静的ファイルが配信され、バイト列が元ファイルと一致する                                                    | FR-06, 07 |
| T3  | ファイルをアップロードして処理を実行し、出力をダウンロードできる                                                  | FR-08〜13 |
| T4  | 上限超過アップロード・実行時間超過が明確なエラーになる                                                            | FR-09, 13 |
| T5  | 2 回連続で実行した際、1 回目の入力・出力が 2 回目から参照できない                                                 | FR-16     |
| T6  | 明示破棄および TTL 満了でアプリが終了し、URL が無効化され、アップロードファイル等が削除済みであることを確認できる | FR-17〜20 |
| T7  | デプロイ途中で失敗させた場合に残存リソースがない                                                                  | FR-21     |
| T8  | ダミーの秘密情報を含むファイルを同梱しようとすると警告される                                                      | NFR-01    |

## 7. リスクと対応方針

| リスク                                                         | 対応                                                                |
| -------------------------------------------------------------- | ------------------------------------------------------------------- |
| セッション由来の任意コード実行による濫用（暗号採掘・踏み台等） | ネットワーク既定遮断（FR-15）、実行時間上限（FR-13）、TTL（FR-17）  |
| 意図しない機密ファイルの公開                                   | 明示選択制（FR-02）、manifest 承認（FR-03）、秘密情報検査（NFR-01） |
| 消去漏れ（削除 API の部分失敗）                                | 冪等な破棄処理とリトライ（FR-21）、破棄後の到達性確認（T6）         |
| cf-apps の仕様不明による手戻り                                 | 要求仕様書 §9 Q1 を最優先で確定してから実装に着手する               |
