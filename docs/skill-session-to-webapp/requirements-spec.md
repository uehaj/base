# 要求仕様書: セッションやりとりの WEB アプリ化スキル（session-to-webapp）

- 文書番号: REQ-S2W-001
- 版: 0.1（ドラフト）
- 作成日: 2026-07-11
- ステータス: 未確定事項あり（§9 の問いに回答後、0.2 へ改版）

## 1. 背景・目的

Claude Code のセッション内では、ファイルを受け取り・加工し・結果を返すといった「やりとり」（対話的なワークフロー）が日常的に行われる。しかしその成果はセッション内に閉じており、第三者が同じ処理をブラウザから再実行することはできない。

本スキル（以下「本スキル」）は、**任意のセッションで行われたやりとり（成果物と処理）を、cf-apps 環境上の使い捨て WEB アプリとして公開する**ことを目的とする。利用者はブラウザから対象ファイルをアップロードして処理を実行でき、アプリは隔離環境で動作し、終了時にはアップロードされたファイルを含めて痕跡なく消滅する。

## 2. 用語定義

| 用語           | 定義                                                                                                                               |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| セッション     | Claude Code の 1 つの会話セッション。成果物ファイル・スクリプト・対話履歴を含む                                                    |
| やりとり       | セッション内で確立されたワークフロー（入力ファイル → 処理 → 出力、およびそれを構成する成果物一式）                                 |
| cf-apps        | アプリのデプロイ先となる Cloudflare ベースのアプリ実行環境（本書では Workers + 静的アセット配信 + 隔離実行機構を想定。§9 Q1 参照） |
| 作成者         | セッションを操作し、本スキルを起動してアプリを生成・公開する Claude Code ユーザー                                                  |
| 利用者         | 公開されたアプリの URL にアクセスし、ファイルをアップロードして処理を実行する人                                                    |
| 手元のファイル | スキル起動時点でセッションの作業ディレクトリに存在するファイル群のうち、アプリに同梱するもの                                       |
| 隔離環境       | 他のアプリ・他の実行から分離され、ホストやネットワークへ意図しない到達ができないサンドボックス実行環境                             |
| 終了           | アプリのライフサイクルの終端。終了と同時にアプリ本体・アップロードファイル・中間生成物がすべて削除される（§9 Q3 参照）             |

## 3. スコープ

### 3.1 対象（In Scope）

- Claude Code のスキル（`/session-to-webapp` 相当）としての提供
- セッション成果物からの WEB アプリ自動生成（UI・アップロード機構・処理実行部の組み立て）
- cf-apps へのデプロイと公開 URL の払い出し
- 手元のファイルの静的配信（無加工での同梱）
- 処理開始前のファイルアップロード機能
- 隔離環境での処理実行
- 終了時の完全消去（アプリ・アップロードファイル・中間生成物・ログ内の入力データ）

### 3.2 対象外（Out of Scope）

- アプリの恒久ホスティング・バージョン管理・再デプロイ運用
- 利用者アカウント管理などの本格的な認証基盤（最小限のアクセス制御は §5 UR-09 で扱う）
- アップロードされたデータの永続保存・再利用
- cf-apps 環境そのものの構築・運用（既存環境の利用を前提とする）
- セッションの対話履歴そのものの公開（本スキルが公開するのは「処理」であり会話ログではない。§9 Q2 参照）

## 4. ステークホルダー

| ステークホルダー | 関心事                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------- |
| 作成者           | セッションの成果を最小の手間で共有可能なアプリにしたい。意図しない公開・課金を避けたい |
| 利用者           | ブラウザだけで処理を実行したい。アップロードしたファイルが残らないことを信頼したい     |
| 環境管理者       | cf-apps のリソース・コスト・セキュリティ境界が守られること                             |

## 5. ユーザー要求（UR）

優先度: **M**=必須（Must）/ **S**=推奨（Should）/ **C**=任意（Could）

| ID    | 優先度 | 要求                                                                                                                   |
| ----- | ------ | ---------------------------------------------------------------------------------------------------------------------- |
| UR-01 | M      | 作成者は、任意のセッション内から 1 コマンド（スキル起動）で、そのセッションのやりとりを WEB アプリとして公開できること |
| UR-02 | M      | アプリは cf-apps 環境上にデプロイされ、公開 URL が作成者に提示されること                                               |
| UR-03 | M      | 手元のファイルは加工されずそのまま静的コンテンツとして配信されること（HTML/CSS/JS/画像/データ等）                      |
| UR-04 | M      | 利用者は、処理の開始前にブラウザからファイルをアップロードできること                                                   |
| UR-05 | M      | 処理は隔離環境で実行され、他の利用者・他のアプリ・デプロイ元環境に影響を与えないこと                                   |
| UR-06 | M      | アプリが終了すると、アップロードされたファイルを含むすべてのデータとアプリ本体が削除されること                         |
| UR-07 | M      | どのファイルを同梱し、何を処理として公開するかを、作成者がデプロイ前に確認・承認できること（意図しない情報公開の防止） |
| UR-08 | S      | 利用者は処理の進行状況と結果（出力ファイルのダウンロード等）をブラウザ上で確認できること                               |
| UR-09 | S      | アプリへのアクセスは推測困難な URL、または簡易トークンで保護できること                                                 |
| UR-10 | S      | 作成者はアプリを明示的に終了（破棄）できること。また無操作のまま放置された場合も一定時間で自動終了すること             |
| UR-11 | C      | 作成者は公開中の自分のアプリを一覧・確認できること                                                                     |
| UR-12 | C      | 同一セッションから設定を変えて再生成（上書きデプロイ）できること                                                       |

## 6. 非機能要求（概要）

詳細は要件定義書 §5 に展開する。

- **セキュリティ**: 隔離実行、秘密情報の非同梱、アップロードファイルの検疫、完全消去
- **プライバシー**: 利用者のアップロード内容を作成者側にもログ等で残さない（処理結果の受け渡しを除く）
- **性能**: 個人〜小規模チーム用途。同時利用者は少数（目安 10 人以下）を想定
- **コスト**: 使い捨て前提。無操作時は課金リソースを保持しない
- **運用性**: 生成・破棄が冪等で、失敗時に中途半端なリソースが残らない

## 7. 制約

- C-01: デプロイ先は cf-apps 環境に限定する
- C-02: 本リポジトリの開発規約に従う（Node 22 / pnpm、Python 3.13 / uv、応答・ドキュメントは日本語）
- C-03: スキルは Claude Code のスキル形式（SKILL.md + 補助スクリプト）で実装する
- C-04: cf-apps 側の実行時間・メモリ・ストレージ上限に従う（具体値は §9 Q1 の回答後に確定）

## 8. 前提・仮定

本書は以下を仮定して記述している。§9 の回答により変更され得る。

- A-01: 「やりとりの WEB アプリ化」とは、**セッションで確立した処理を第三者がファイルをアップロードして再実行できるアプリにすること**を指す（会話ログビューアやチャット再現ではない）
- A-02: cf-apps は Cloudflare 系の環境であり、(a) 静的アセット配信、(b) HTTP ハンドラ、(c) 隔離されたコード実行（サンドボックス/コンテナ）、(d) 一時ストレージ、(e) API/CLI によるデプロイと削除、を提供する
- A-03: デプロイに必要な認証情報（API トークン等）はセッション環境の環境変数として供給される
- A-04: 処理本体はセッションで作成されたスクリプト（Node.js または Python）である

## 10. 受け入れ判定（要求レベル）

以下がすべて満たされたとき、本要求仕様は充足されたとみなす。

1. 任意のセッションでスキルを起動し、確認・承認を経て公開 URL が得られる（UR-01, 02, 07）
2. 同梱した静的ファイルが無加工で配信される（UR-03）
3. 利用者がファイルをアップロードして処理を実行し、結果を取得できる（UR-04, 08）
4. 処理が隔離環境で実行されることが構成上保証される（UR-05）
5. 終了後、アプリ URL が無効化され、アップロードファイル・中間生成物が復元不能に削除されたことが確認できる（UR-06, 10）
