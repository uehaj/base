# 要求仕様書: セッション対話 WEB アプリ化スキル(仮称: session-webapp)

- 版数: 0.1(ドラフト)
- 作成日: 2026-07-11
- 状態: **未確定事項あり(§8 参照)。発注者の回答を得て 0.2 に更新する。**

---

## 1. 背景・目的

Claude Code のセッションで行われたやりとり(ユーザーとアシスタントの対話、成果物)は、セッション終了後はターミナルやログの中に留まり、第三者への共有や後からの参照がしづらい。

本スキルは、**任意のセッションでのやりとりを WEB アプリとして閲覧・利用できる形に変換し、cf-apps 環境にデプロイする**ことを目的とする。あわせて、手元のファイルを静的コンテンツとしてそのまま配信でき、処理開始前のファイルアップロードも受け付ける。実行は隔離環境で行い、**終了時にはアップロードされたファイルを含めて環境ごと消去される**ことを保証する。

## 2. 用語

| 用語         | 定義                                                                                                                                      |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- |
| スキル       | Claude Code の Skill(`.claude/skills/` 配下に置くスラッシュコマンド相当の機能単位)                                                        |
| セッション   | Claude Code の 1 つの会話セッション。トランスクリプト(やりとりの記録)を持つ                                                               |
| cf-apps 環境 | 本書では **Cloudflare 上のアプリ実行環境(Workers の静的アセット配信 + 隔離実行: Sandbox/Containers)** を指すと仮定する(仮定 A-1、§8 問 1) |
| 静的配信     | 手元のファイルを変換せずそのまま HTTP で配信すること                                                                                      |
| 隔離環境     | 他の環境・本番データから分離された使い捨ての実行環境                                                                                      |
| 実行者       | 本スキルを Claude Code 上で起動する開発者(本人)                                                                                           |
| 利用者       | デプロイされた WEB アプリをブラウザで使う人(実行者本人または共有先)                                                                       |

## 3. スコープ

### 3.1 対象(In Scope)

1. セッションのやりとりを WEB アプリ化するスキル本体(SKILL.md + 支援スクリプト)。
2. 手元ファイルの静的配信(無変換)。
3. WEB アプリ利用者による「処理開始前」のファイルアップロード機能。
4. 隔離環境での実行と、終了時の完全消去(アップロードファイル含む)。
5. デプロイ先 URL の発行と実行者への提示。

### 3.2 対象外(Out of Scope)

- 恒久的なホスティング/永続ストレージ(意図的に持たない)。
- セッションの編集・改変機能(閲覧・利用が目的)。
- cf-apps 環境自体の構築・契約(既存の環境を利用する前提)。
- 多言語 UI(初版は日本語のみ)。

## 4. ステークホルダー

| 役割           | 関心事                                                             |
| -------------- | ------------------------------------------------------------------ |
| 実行者(開発者) | ワンコマンドでデプロイでき、消し忘れが起きないこと                 |
| 利用者(共有先) | URL を開くだけで使えること。アップロードしたファイルが残らないこと |
| 環境管理者     | コスト・セキュリティ(公開範囲、残留データゼロ)                     |

## 5. 要求一覧

要求 ID は `REQ-<番号>`。優先度: M=必須 / S=推奨 / C=任意。

| ID     | 要求                                                                                                                 | 優先度 |
| ------ | -------------------------------------------------------------------------------------------------------------------- | ------ |
| REQ-01 | 任意のセッションを指定して、そのやりとり(トランスクリプト)を WEB アプリとして閲覧できる形に変換・デプロイできること  | M      |
| REQ-02 | デプロイは cf-apps 環境上で行うこと                                                                                  | M      |
| REQ-03 | 実行者が指定した手元のファイル群を、変換せずそのまま静的コンテンツとして配信できること                               | M      |
| REQ-04 | WEB アプリの利用者が「処理開始前」にブラウザからファイルをアップロードでき、以降の処理でそのファイルを利用できること | M      |
| REQ-05 | アプリの実行(アップロードファイルを扱う処理を含む)は隔離環境で行うこと                                               | M      |
| REQ-06 | 環境の終了時に、アップロードされたファイルを含む全データ(アプリ本体・トランスクリプト・一時データ)が消去されること   | M      |
| REQ-07 | 終了は明示操作に加え、消し忘れ防止のための自動失効(タイムアウト)を備えること                                         | S      |
| REQ-08 | デプロイ完了時に、アクセス用 URL と終了方法を実行者に提示すること                                                    | M      |
| REQ-09 | URL は推測困難であること。必要に応じてアクセス制限(認証)を追加できること                                             | S      |
| REQ-10 | トランスクリプトに含まれる秘密情報(トークン等)の混入を警告・マスキングできること                                     | S      |
| REQ-11 | スキルは本リポジトリ(`base`)の `.claude/skills/` に配置し、他リポジトリへ移植可能な構成とすること                    | S      |
| REQ-12 | 1 回のデプロイ〜消去のサイクルが課金・リソース面で軽量であること(常駐リソースを持たない)                             | S      |

## 6. 制約

| ID     | 制約                                                                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| CON-01 | cf-apps 環境のアカウント・認証情報(API トークン等)は実行者が事前に用意する。スキルはそれを前提とする                                            |
| CON-02 | 本リポジトリの方針(CLAUDE.md)に従う: 応答は日本語、一時ファイルは `workdir/`、コミットは Conventional Commits                                   |
| CON-03 | アップロードファイルは隔離環境の外(永続ストレージ、外部サービス)へ持ち出さない                                                                  |
| CON-04 | 環境が提供する上限(リクエストサイズ、実行時間、ストレージ量)に従う。Cloudflare 前提の場合、アップロードサイズは 100 MB/リクエスト程度が上限目安 |

## 7. 前提・仮定

| ID  | 前提・仮定                                                                                                                   | 確定状況            |
| --- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| A-1 | cf-apps = Cloudflare のアプリ実行環境(Workers 静的アセット + Sandbox/Containers による隔離実行)である                        | **未確定**(§8 問 1) |
| A-2 | 「やりとりの WEB アプリ化」の初版の中心は「トランスクリプトの閲覧・共有アプリ」であり、対話継続(チャット)機能は初版対象外    | **未確定**(§8 問 2) |
| A-3 | アップロード主体は「WEB アプリの利用者(ブラウザ)」。実行者の手元ファイルはデプロイ時に静的配置される(アップロードとは別経路) | **未確定**(§8 問 3) |
| A-4 | 終了は「明示終了 + タイムアウト保険」の両建て                                                                                | **未確定**(§8 問 4) |
| A-5 | トランスクリプトの取得元は Claude Code のローカルセッション記録(`~/.claude/projects/` 配下の JSONL 等)                       | 実装時に検証        |

## 8. 確認事項(問)

ユーザーより「更に問あり」とのことなので、以下を確認したい。**回答により §5〜7 と要件定義書を改版する。**

1. **cf-apps の正体**: Cloudflare(Workers/Pages/Containers)を指すか。それとも社内・自作の環境、Cloud Foundry(`cf apps`)、あるいは別のものか。
2. **「やりとりの WEB アプリ化」の姿**: (a) 会話ログの閲覧・共有アプリ、(b) ブラウザから対話を継続できるチャットアプリ、(c) セッション成果物(HTML 等)のそのまま公開 — のどれが主目的か(複数可、優先順位)。
3. **アップロード主体**: 「処理開始前にアップロード」は、WEB アプリ利用者がブラウザから行うものか、実行者がデプロイ時に追加投入するものか(両方か)。またその「処理」とは何を指すか(例: アップロードしたファイルをアプリが解析・表示する)。
4. **終了・削除の契機**: 明示終了のみ/タイムアウトのみ/両方。タイムアウトの目安時間(例: 無操作 30 分、最長 24 時間)。
5. **公開範囲**: URL を知っていれば誰でもアクセス可でよいか。パスワード・Cloudflare Access 等の認証が必要か。
6. **「更に問あり」の内容**: 上記以外に想定している追加要件・質問があれば提示いただきたい。
