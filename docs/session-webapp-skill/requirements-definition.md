## 1. システム概要

本スキルは、Claude Code 上で起動する 1 コマンドのワークフローとして実現する。

```
実行者 ──(1) /session-webapp <セッション指定> [--static <dir>] ──▶ Claude Code(スキル)
                                                                    │
        (2) トランスクリプト抽出・秘密情報検査                        │
        (3) ビューア + アップロード UI + 静的ファイルをバンドル        │
        (4) cf-apps 環境へデプロイ(隔離環境を新規作成)               ▼
                                                            ┌─────────────────┐
利用者 ──(5) ブラウザでアクセス/ファイルアップロード ──────▶ │ 隔離環境(使い捨て) │
                                                            │ ・静的配信          │
実行者 ──(6) /session-webapp stop または タイムアウト ─────▶ │ ・アップロード処理   │
                                                            └──── 全消去 ────────┘
```

### 1.1 構成要素

| 要素               | 内容                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------- |
| スキル定義         | `.claude/skills/session-webapp/SKILL.md`(手順・プロンプト)                                  |
| 変換スクリプト     | セッション JSONL → 閲覧用アプリデータ(JSON/HTML)への変換(Node、`node --test` でテスト)      |
| アプリテンプレート | トランスクリプトビューア + アップロード UI(静的 HTML/JS/CSS、ビルド不要構成)                |
| デプロイスクリプト | cf-apps 環境への作成・配置・破棄(★A-1: Cloudflare なら wrangler / Sandbox SDK を利用)       |
| 状態ファイル       | デプロイ中の環境 ID・URL・期限を `workdir/session-webapp/state.json` に記録(消し忘れ検出用) |

## 2. 機能要件

ID は `FR-<番号>`。[REQ-xx] は要求仕様書との対応。

### 2.1 スキル起動・入力(FR-01〜03)

- **FR-01** [REQ-01] スキルは対象セッションを次のいずれかで指定できる: (a) 現在のセッション、(b) セッション ID、(c) セッション一覧からの選択。
- **FR-02** [REQ-03] `--static <dir>` で指定したディレクトリ配下のファイルを**無変換で**静的配信対象に含める。省略時は静的ファイルなし。
- **FR-03** 入力検証: 対象セッションが存在しない/読めない場合、静的ディレクトリが存在しない場合は、デプロイ前に日本語のエラーで中断する。

### 2.2 トランスクリプト変換(FR-04〜06)

- **FR-04** [REQ-01] セッション記録(★A-5: `~/.claude/projects/` 配下の JSONL)から、ユーザー発話・アシスタント応答・主要なツール実行の要約を時系列で抽出し、閲覧用データに変換する。
- **FR-05** [REQ-10] 変換時に秘密情報らしきパターン(API キー、トークン、秘密鍵、`Authorization:` ヘッダ等)を検査し、検出時は (a) 一覧を実行者に提示し、(b) マスキングして続行するか中断するかを確認する。
- **FR-06** 変換結果はマークダウンレンダリング・コードハイライト付きで閲覧できる形式とする。

### 2.3 WEB アプリ(FR-07〜10)

- **FR-07** [REQ-01] ★A-2 ビューア画面: やりとりを会話形式で表示。目次(発話単位)ジャンプ、テキスト検索を備える。
- **FR-08** [REQ-03] 静的ファイルはアップロード時のパス構造を保ったまま `/static/` 配下で配信する。Content-Type は拡張子から決定し、内容の書き換えは行わない。
- **FR-09** [REQ-04] ★A-3 アップロード画面: 利用者は「処理開始」前に 1 つ以上のファイルをブラウザからアップロードできる。処理開始後の追加アップロードは受け付けない(明確に無効化する)。
- **FR-10** [REQ-04] アップロードされたファイルは隔離環境内のみに保存され、アプリの「処理」(★問 3: 内容の表示・解析等。確定後に詳細化)から参照できる。

### 2.4 隔離実行(FR-11〜12)

- **FR-11** [REQ-05] アップロードファイルを扱う処理は、デプロイごとに新規作成される隔離環境内で実行する。環境間・他テナントとの共有ストレージを持たない。
- **FR-12** [REQ-05] 隔離環境から実行者のローカルマシン・リポジトリへの書き戻しは行わない(結果はブラウザ表示のみ)。

### 2.5 終了・消去(FR-13〜16)

- **FR-13** [REQ-06] `/session-webapp stop`(または `--stop`)で、アプリ本体・トランスクリプトデータ・静的ファイル・**アップロードファイルを含む隔離環境全体**を削除する。
- **FR-14** [REQ-07] ★A-4 自動失効: デプロイ時に TTL(既定 24 時間、オプションで変更可)を設定し、期限到達で環境を自動破棄する。
- **FR-15** [REQ-06] 削除後に URL へアクセスした場合は 404/410 を返し、データが残存しないことを確認できる。
- **FR-16** [REQ-08] スキル起動時に既存の稼働中デプロイ(state.json)を検出した場合、その URL と期限を提示し、破棄するか継続するかを確認する。

### 2.6 実行者への提示(FR-17)

- **FR-17** [REQ-08] デプロイ完了時に次を提示する: アクセス URL、TTL(自動消滅時刻)、停止コマンド、静的配信の有無とパス、秘密情報検査の結果サマリ。

## 3. 非機能要件

ID は `NFR-<番号>`。

| ID     | 分類         | 要件                                                                                                                     |
| ------ | ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| NFR-01 | セキュリティ | [REQ-09] URL に推測困難なランダム識別子(128bit 相当以上)を含める                                                         |
| NFR-02 | セキュリティ | [REQ-09] ★問 5: オプションで簡易認証(パスワード or Cloudflare Access)を有効化できる                                      |
| NFR-03 | セキュリティ | [CON-03] アップロードファイル・トランスクリプトを隔離環境外の永続ストレージ・ログ・外部サービスへ出力しない              |
| NFR-04 | プライバシー | 削除は「環境ごと破棄」により実現し、個別ファイル削除漏れが構造的に起きない方式とする                                     |
| NFR-05 | 性能         | デプロイ完了まで 3 分以内(通常セッション・静的ファイル 50 MB 以下の場合)。ビューア初期表示 3 秒以内                      |
| NFR-06 | 容量         | [CON-04] アップロード 1 ファイル上限・合計上限を設け(既定: 25 MB / 100 MB、環境上限以下)、超過時は UI でエラー表示       |
| NFR-07 | コスト       | [REQ-12] 常駐リソースを持たず、稼働中のみ課金される構成とする。デプロイ時に概算コストの目安を提示                        |
| NFR-08 | 可搬性       | [REQ-11] スキルはリポジトリ固有パスに依存せず、`.claude/skills/session-webapp/` を丸ごとコピーして他リポジトリで利用可能 |
| NFR-09 | 保守性       | 変換スクリプトは `node --test`、Python を使う場合は pytest でテスト可能とする(本リポジトリの標準に従う)                  |
| NFR-10 | 運用         | 失敗時(デプロイ途中エラー等)は作りかけの環境を自動でロールバック削除する                                                 |

## 4. 外部インターフェース

### 4.1 スキルコマンド(案)

```
/session-webapp                     # 現在のセッションをアプリ化してデプロイ
/session-webapp <session-id>        # 指定セッションをデプロイ
/session-webapp --static ./public   # 静的ファイルを含める
/session-webapp --ttl 2h            # 自動失効を 2 時間に
/session-webapp stop                # 稼働中の環境を即時破棄
/session-webapp status              # URL・残り TTL の確認
```

### 4.2 WEB アプリの画面(案)

| 画面         | 内容                                                     |
| ------------ | -------------------------------------------------------- |
| ビューア     | 会話の時系列表示、検索、目次                             |
| アップロード | 処理開始前のみ有効なファイル投入 UI + 「処理開始」ボタン |
| 静的配信     | `/static/...` 直下でそのまま配信(画面ではなくパス)       |

### 4.3 cf-apps 環境とのインターフェース(★A-1)

Cloudflare 前提の場合: wrangler(デプロイ/削除)、Workers Static Assets(静的配信)、Sandbox/Containers(アップロード処理の隔離実行)、API トークンは環境変数 `CLOUDFLARE_API_TOKEN` で受け取る。**A-1 が否定された場合、本節は全面差し替え。**

## 5. データライフサイクル

| データ                 | 生成         | 保存場所                       | 消去タイミング                    |
| ---------------------- | ------------ | ------------------------------ | --------------------------------- |
| トランスクリプト変換物 | デプロイ時   | 隔離環境内                     | stop / TTL 失効                   |
| 静的ファイル(複製)     | デプロイ時   | 隔離環境内                     | stop / TTL 失効                   |
| アップロードファイル   | 利用者操作時 | 隔離環境内のみ                 | stop / TTL 失効(=環境ごと破棄)    |
| 処理の中間・結果データ | 処理実行時   | 隔離環境内のみ                 | 同上                              |
| state.json(URL・期限)  | デプロイ時   | 実行者の `workdir/`(gitignore) | stop 時に削除。秘密情報は含めない |

## 6. 受け入れ基準(抜粋)

1. 任意のセッションを指定してデプロイし、発行 URL で会話が閲覧できる(FR-01/04/07)。
2. `--static` で渡したファイルがバイト一致で配信される(FR-08)。
3. ブラウザからアップロードしたファイルが処理から参照でき、処理開始後はアップロード UI が無効化される(FR-09/10)。
4. `stop` 実行後、URL が 404/410 になり、アップロードファイルを含む全データが取得不能である(FR-13/15)。
5. TTL 経過後、操作なしで同様に消滅している(FR-14)。
6. トランスクリプトにダミー API キーを混入させた場合、デプロイ前に警告が出る(FR-05)。

## 7. リスクと対応

| リスク                          | 対応                                                   |
| ------------------------------- | ------------------------------------------------------ |
| cf-apps の解釈違い(A-1)         | 問 1 の回答までデプロイ層をアダプタとして分離設計      |
| トランスクリプト形式の変更(A-5) | 変換層を分離し、フォーマット判定+テストで検知          |
| 秘密情報の公開事故              | FR-05 の事前検査 + NFR-01/02 のアクセス制御 + 既定 TTL |
| 消し忘れ                        | FR-14 の TTL + FR-16 の稼働中検出                      |
